# WHENCOMMAND — 기술 스펙과 결정 기록

> 프로젝트 정의는 [01_프로젝트.md](01_프로젝트.md), 요구사항 ID는 [02_요구사항.md](02_요구사항.md). 2026-09-19 v0.1.

## 1. 스택 (형제 앱과 동일)

Electron 43 · vanilla JS + CSS(프레임워크 없음) · `node:sqlite` 단일 파일 · electron-builder · 미서명 GitHub Releases + electron-updater.

형제 앱과 다른 점은 **없다.** WHENMUSIC이 네이티브 애드온 하나로 갈라졌던 것과 달리, 이 앱은 Electron 기본 API만으로 전부 된다 — `globalShortcut`, `BrowserWindow`, `shell.openPath`, `child_process`. 런타임 의존성은 `electron-updater` 하나다.

**두 OS를 동등하게 낸다**는 점만 형제 앱과 다르다. 지금까지 다섯 앱은 Windows가 주였고 macOS는 미검증 상태였다([D-13](#d-13-macos를-1급으로-낸다)).

### 식별자

| | 값 |
|---|---|
| appId | `com.when630.whencommand` |
| productName | `WHENCOMMAND` |
| 저장소 | `%APPDATA%\whencommand` · `~/Library/Application Support/whencommand` |
| 스크립트 폴더 | `~/.whencommand/scripts/` (양 OS 공통) |
| 연동 폴더 | `~/.when/apps/` (양 OS 공통, 형제 앱과 공유) |

## 2. 모듈 구조

```
main/
  index.mjs        부트스트랩 (형제 앱과 동일, 8줄)
  lifecycle.mjs    앱 수명 · 트레이 · 전역 단축키 · 창 소유
  panel.mjs        입력줄 창 — 미리 만들고 숨긴다 (D-06)
  toast.mjs        짧은 스크립트 출력용 토스트 창 — 포커스를 받지 않고 클릭이 통과한다 (D-17)
  scripts.mjs      스크립트 헤더 파싱 · 출력 분기 · 오류 줄 찾기 — 순수 함수 (EXT)
  place.mjs        창 자리 계산 — 순수 함수 (whenwork 승계)
  ipc.mjs          렌더러 경계
  search.mjs       초성 · 퍼지 매칭 — 순수 함수 (whennote 승계)
  rank.mjs         frecency 점수 — 순수 함수 (D-10)
  manifest.mjs     형제 앱 매니페스트 파싱 · 검증 — 순수 함수
  store.mjs        node:sqlite
  settings.mjs     (형제 앱 승계, 42줄)
  update.mjs       (whenwork 승계, 181줄)
  sources/         결과 공급원 — 전부 같은 모양이다 (D-11)
    index.mjs        등록 · 병합 · 비동기 합류
    apps.mjs         설치된 앱
    files.mjs        OS 인덱스 위임
    calc.mjs         계산 · 단위 변환
    scripts.mjs      셸 스크립트
    siblings.mjs     형제 앱 명령
  platform/        OS 분기는 여기 안에만 (PLAT-01)
    index.mjs · darwin.mjs · win32.mjs
renderer/
  panel.html · panel.js · tokens.css · icons.js
```

`sources/`가 이 앱의 뼈대다. **모든 결과는 같은 모양의 공급원에서 나온다** — 앱도, 파일도, 형제 앱 명령도, 계산 결과도 예외가 아니다. 새 기능은 대개 `sources/`에 파일 하나를 더하는 일이 된다.

```js
// sources/*.mjs 는 전부 이 모양이다
export default {
  id: 'apps',
  ready: async () => {},              // 시작 시 1회. 캐시를 채운다
  query: async (q, ctx) => [item],    // 결과. 느려도 된다 (D-11)
};

// item
{ id, source, title, subtitle, icon, base, run, alt }
//                                    ↑ 0~1 매칭 점수. 최종 정렬은 rank.mjs가 한다
```

## 4. 데이터 모델 (v1 스키마)

저장하는 것은 랭킹뿐이다(STOR-02). 검색어 원문은 남기지 않는다 — 무엇을 검색했는지가 아니라 **무엇을 골랐는지**만 필요하다.

```sql
CREATE TABLE picks (
  key       TEXT PRIMARY KEY,   -- 'apps:/Applications/Chrome.app'
  source    TEXT NOT NULL,
  hits      INTEGER NOT NULL DEFAULT 0,
  last_at   INTEGER NOT NULL    -- epoch ms
);
CREATE INDEX picks_last ON picks(last_at DESC);

CREATE TABLE meta (k TEXT PRIMARY KEY, v TEXT);  -- 스키마 버전 등
```

테이블이 둘뿐인 것이 정상이다. 형제 앱의 `store.mjs`가 600~850줄인 반면 이 앱은 100줄을 넘지 않아야 한다 — 넘으면 이 앱이 데이터를 갖기 시작했다는 뜻이고, [01의 원칙](01_프로젝트.md#설계-원칙--형제-앱과의-대칭)이 깨진 것이다.

## 5. 검색과 랭킹 — 이 앱의 핵심 난제

체감 품질의 대부분이 여기서 결정된다. **두 글자를 치면 원하는 것이 첫 줄에 있어야 한다**(SRCH-04).

### 매칭 (`search.mjs`, 순수 함수)

`whennote/main/search.mjs`를 복사해 시작한다. 세 경로를 전부 본다.

| 경로 | 예 | 비고 |
|---|---|---|
| 초성 | `ㅋㄹ` → 크롬 | whennote에 이미 있다 |
| 퍼지(서브시퀀스) | `vsc` → Visual Studio Code | 연속 매칭·단어 첫 글자에 가산점 |
| 자판 오타 교정 | `퍼갸ㅑㅔ` → chrome | 한↔영 자판 매핑 후 재시도 (SRCH-03) |

점수는 0~1로 정규화한다. **연속해서 맞은 구간**과 **단어 첫 글자에서 맞은 것**에 같은 가산점을 준다 — `chr`이 "**C**ache **H**andler **R**unner"의 머리글자 셋보다 "**Chr**ome"의 연속 세 글자에서 높아야 한다(처음엔 연속 가산이 낮아 흩어진 머리글자가 항상 이겼다). 거기에 밀집도(글자가 몇 칸에 몰렸나)와 커버리지(대상을 얼마나 덮었나)를 곱해 정확히 같으면 1이 된다.

### 랭킹 (`rank.mjs`, 순수 함수)

매칭 점수만으로 정렬하면 이름이 짧은 것이 항상 이긴다. 실제로 원하는 것은 **내가 자주 고른 것**이다.

```js
// 최근성 계수 — 버킷으로 끊는다. 연속 함수보다 예측 가능하고 테스트하기 쉽다
const recency = (ms) =>
  ms <   3600e3 ? 4     // 1시간 내
: ms <  86400e3 ? 2     // 하루 내
: ms < 604800e3 ? 1     // 일주일 내
:                 0.4;

// 최종 점수
final = base * (1 + Math.log1p(hits) * recency(now - last_at));
```

`log1p`를 쓰는 이유는 100번 고른 것이 10번 고른 것을 10배로 누르면 안 되기 때문이다 — 새로 설치한 앱이 영영 못 올라온다. 곱셈으로 묶는 이유는 **매칭이 0이면 아무리 자주 골랐어도 나오면 안 되기** 때문이다.

이 두 함수는 Electron 없이 `test/`에서 검증한다. 규칙을 바꾸면 테스트가 먼저 바뀐다.

## 6. 입력줄 창의 제약

| 제약 | 방법 | 확인 필요 |
|---|---|---|
| 120ms 내 표시 | 창을 미리 만들어 `hide()`로 숨겨 둔다. `show()`만 한다 (D-06) | 양 OS 실측 |
| 전체화면 위 | `setAlwaysOnTop(true, 'screen-saver')` + `setVisibleOnAllWorkspaces(true, { visibleOnFullScreen: true })` | macOS 실측 |
| 포커스 복귀 | macOS `app.hide()` 로 앱 단위 숨김 → OS가 직전 앱으로 돌려준다. Windows는 이전 foreground 핸들을 기억해 복원 | 양 OS 실측 |
| 프레임 없음 | `frame: false, transparent: true, resizable: false, skipTaskbar: true` | — |
| 커서 있는 화면 | `screen.getDisplayNearestPoint(screen.getCursorScreenPoint())` → `place.mjs` | — |

**포커스 복귀(PANEL-06)가 가장 까다롭다.** 두 OS의 방식이 다르고, 이걸 놓치면 앱을 부를 때마다 작업이 끊겨 앱 전체가 쓸모없어진다. `platform/` 안에서 갈라 두고 계약 테스트로 묶는다.

## 7. 명령 규약 (`when-protocol`)

별도 저장소에 둔다([D-12](#d-12-규약은-별도-저장소에-둔다)). 스키마·예제·각 앱이 붙이는 법이 거기 있다.

```jsonc
// ~/.when/apps/whennote.json — 형제 앱이 스스로 떨어뜨린다
{
  "protocol": 1,
  "id": "whennote",
  "name": "WHENNOTE",
  "scheme": "whennote",              // whennote://... 로 부른다
  "verify": {                        // 실제 설치 여부 확인용 (LINK-04)
    "darwin": "/Applications/WHENNOTE.app",
    "win32":  "%LOCALAPPDATA%\\Programs\\WHENNOTE\\WHENNOTE.exe"
  },
  "commands": [                      // 2026-09-21 WHENNOTE가 실제로 쓰는 넷(whennote main/deeplink.mjs)
    { "id": "capture", "title": "퀵 메모",    "args": [{ "name": "text", "type": "string", "optional": true }] },
    { "id": "search",  "title": "메모 검색",  "args": [{ "name": "q", "type": "string" }] },
    { "id": "new",     "title": "새 메모",    "args": [{ "name": "text", "type": "string", "optional": true }] },
    { "id": "open",    "title": "메모 창 열기" }
  ]
}
```

실행은 딥링크 한 줄이다 — `shell.openExternal('whennote://search?q=회의')`. 앱이 꺼져 있으면 OS가 띄워 주고, 떠 있으면 `second-instance`·`open-url`로 기존 인스턴스에 전달된다. 형제 앱은 이미 `requestSingleInstanceLock()`을 쓰고 있어서 받을 준비의 절반은 돼 있다.

**형제 앱이 해야 할 일은 둘뿐이다** — `setAsDefaultProtocolClient(scheme)` 한 줄과, 매니페스트 파일 쓰기. WHENNOTE는 2026-09-21에 붙였다(그쪽 D-13). 나머지 넷은 when-protocol README의 세 단계를 따른다. **붙이지 않아도 그 앱은 그대로 동작한다.**

v1은 딥링크까지만 한다. 결과를 입력줄 **안에서** 보여 주는 라이브 조회(`mode: "live"`)는 양방향 IPC가 필요해 v2로 미룬다([오픈이슈 #2](#오픈이슈)).

## 8. IPC 채널

형제 앱 규약대로 `domain:action`이고, 렌더러는 `contextBridge.exposeInMainWorld('whencommand', …)`로 받는다.

| 채널 | 방향 | 내용 |
|---|---|---|
| `app:init` | invoke | 설정 · 단축키 표기 · 첫 실행 여부 |
| `query:run` | invoke | 입력 문자열 → 즉시 결과 |
| `query:more` | on | 늦게 도착한 공급원의 추가 결과 (D-11) |
| `item:run` | invoke | 항목 실행 → 랭킹 기록 → 창 숨김 |
| `item:alt` | invoke | 보조 동작 (폴더 열기 등) |
| `script:output` | on | 스크립트의 긴 출력·실패 → 패널이 출력 모드로 (EXT-04·05) |
| `script:rerun` / `script:open` | invoke | 출력 모드의 `↵` 다시 실행 · `⌘/Ctrl+↵` 스크립트 열기 |
| `clip:copy` | invoke | 출력 모드의 `⌘/Ctrl+C` — 샌드박스 렌더러는 클립보드를 못 만진다 |
| `toast:show` | on (토스트 창) | 짧은 출력 — 제목·본문·복사 여부·걸린 시간 |
| `settings:get` | invoke | 설정 창의 전부 — 단축키 상태·자동 실행·스크립트 수·형제 앱(연결/건너뜀+이유)·버전 |
| `settings:autostart` / `settings:openScripts` / `settings:openSiblings` / `settings:refreshLists` | invoke | 자동 실행은 되읽은 값을 돌려준다(PLAT-05) |
| `settings:export` / `settings:import` | invoke | 설정 JSON — hotkey·openAtLogin·panel.pos (STOR-04). 가져온 단축키가 안 잡히면 이전 조합 유지 |
| `store:reset` / `panel:resetPosition` | invoke | 랭킹 초기화(STOR-03) · 입력줄 자리 되돌리기(D-19) |
| `settings:resize` / `settings:close` | send | 설정 창 높이 · 닫기 |
| `hotkey:set` | invoke | 등록 실패를 **돌려준다** (PLAT-02) |
| `update:check` / `update:install` | invoke | — |
| `win:hide` | send | — |

## 9. 테스트 · CI

Electron 없이 도는 순수 함수가 이 앱의 대부분이다 — 형제 앱보다 테스트 비중이 높다.

| 대상 | 검증 |
|---|---|
| `search.mjs` | 초성 · 퍼지 · 자판 교정. 알려진 입력 → 기대 순위 |
| `rank.mjs` | 매칭 0이면 결과 0. 빈도 100 vs 10이 10배가 아님. 최근성 버킷 경계 |
| `place.mjs` | 멀티 디스플레이 · 화면 밖 방지 (whenwork 테스트 승계) |
| `manifest.mjs` | 깨진 JSON · 없는 필드 · 모르는 `protocol` 버전 → 그 파일만 건너뜀 (LINK-05) |
| `platform.test.mjs` | darwin · win32 구현이 같은 모양인지 계약 검사 (PLAT-01) |

CI는 세 OS에서 돈다(`.github/workflows/ci.yml` — 푸시·PR마다 `npm test`, xvfb 없이 — 순수 함수뿐이라). 릴리스(`release.yml`)는 태그 `v*`에 테스트 → 두 OS 빌드(패키징 전 `smoke`) → Releases 드래프트, WHENNOTE 것을 복사. 형제 앱은 Windows만 돌렸지만 이 앱은 양쪽을 낸다(REL-01).

## 10. 결정 기록

새 결정은 여기 `D-nn`으로 남기고 **폐기안도 함께 적는다.**

### D-01 스택은 형제 앱 계열이다
Electron 43 · 바닐라 JS · `node:sqlite` · electron-builder · 미서명 배포. 여섯 번째 앱이 스택을 바꾸면 시리즈가 갈라진다. **폐기안:** Tauri 2 — 상주 메모리가 앱당 40~80MB로 Electron의 1/3이고 런처는 상시 상주라 매력적이었다. 그러나 형제 앱의 `platform/`에 쌓인 실패 지식(미서명 로그인 항목, 트레이 숨김 영역, 단축키 조용한 실패)을 Rust로 다시 밟아야 하고, 시리즈에서 이 앱만 이질적인 스택이 된다. 렌더러가 바닐라라 이식 자체는 쉬웠다는 점만 기록해 둔다.

### D-02 자기 명사를 갖지 않는다
할 일·메모·일정·소리·사람 중 무엇도 만들지 않는다. 저장하는 것은 랭킹뿐이다. 이 앱이 데이터를 갖기 시작하면 형제 앱과 기능이 겹치기 시작한다 — `store.mjs`가 100줄을 넘으면 경고 신호다.

### D-03 형제 앱이 하나도 없어도 온전히 동작한다
사용자가 다섯 앱을 전부 쓰지 않고 필요한 것만 골라 설치한다(2026-09-19 확인). 따라서 앱 실행·파일 열기·계산·스크립트만으로 v1이 성립해야 하고, 연동은 **더해지는 것**이지 전제가 아니다. `~/.when/apps/`가 없으면 오류도 안내도 없이 그냥 넘어간다(LINK-01). 반대 방향도 같다 — 형제 앱은 이 앱이 없어도 그대로 동작한다.

### D-04 연동은 파일 기반 수동적 발견이다
형제 앱이 `~/.when/apps/<id>.json`을 떨어뜨리고 WHENCOMMAND가 읽는다. **폐기안 ①** 각 앱의 SQLite를 직접 읽기 — 스키마가 바뀔 때마다 이 앱이 깨지고, 다섯 앱의 스키마를 이 앱이 알아야 한다. **폐기안 ②** 앱이 실행 중일 때 소켓으로 등록 — 앱이 꺼져 있으면 명령이 목록에서 사라져 "있다가 없다가" 한다. 파일은 앱이 꺼져 있어도 남는다.

### D-05 단축키만은 OS별로 다르게 둔다
macOS `⌘Space`, Windows `Alt+Space`. 형제 앱은 두 OS에 같은 조합을 일부러 썼지만(손가락을 다시 안 배우게), **이 앱은 시리즈에서 가장 자주 누르는 키**라 각 OS의 관례를 따르는 편이 이익이 크다 — macOS 사용자는 `⌘Space`에 이미 손이 가 있고(Spotlight), Windows는 `Alt+Space`가 PowerToys Run의 자리다. **폐기안:** `Ctrl+Alt+<글자>` 통일 — 형제 앱과 일관되지만 세 손가락이고, 남은 글자가 마땅치 않았다(`C`는 WHENCALENDAR가 쓴다). 대가는 [PLAT-03·04](02_요구사항.md#플랫폼-plat)의 충돌 안내다.

### D-06 창은 미리 만들어 숨겨 둔다
`show()`/`hide()`만 하고 `close()`하지 않는다. 매번 `BrowserWindow`를 만들면 렌더러 초기화에만 수백 ms가 들어 120ms 예산(PANEL-02)을 못 지킨다. 대가는 상주 메모리인데, 어차피 트레이 앱이라 이미 떠 있다. **(2026-09-19 실측)** 미리 만든 창 27ms vs 새 창 133ms로 확정. 설치 직후 첫 실행의 첫 페인트만 446ms(콜드 캐시)라, 시작 직후 한 번 보이지 않게 그려 두는 워밍업은 넣되 그 이유를 이렇게 적어 둔다(§11 #6).

### D-07 확장은 셸 스크립트다
`~/.whencommand/scripts/`의 실행 파일이 곧 명령이다. **폐기안:** Raycast식 JS 확장 API — 만드는 순간 그 API가 제품이 되어 문서·버전·샌드박스·심사가 따라온다. 1인 사용자에게 셸 스크립트가 같은 일을 하고 비용이 0이다. 스크립트가 부족해지면 그때 다시 본다.

### D-08 입력줄은 화면 위 28% 중앙이다
WHENCALENDAR가 상단 중앙, WHENMUSIC이 우하단을 쓴다. 28% 지점은 상단 아일랜드 아래이고, `whenwork/main/place.mjs`의 `centerY:false`가 정확히 이 값이다 — 복사해 쓴다. 순간적으로만 뜨므로 WHENCALENDAR와 잠깐 겹쳐도 허용한다.

### D-09 파일 검색은 OS 인덱스에 위임한다
macOS `mdfind`, Windows Search. **폐기안:** 자체 인덱서 — 두 OS가 이미 커널 수준에서 같은 일을 하고 있어 배터리와 디스크를 두 번 쓴다. Everything SDK는 Windows에서 훨씬 빠르지만 사용자가 별도 설치해야 해 "설치 파일 하나로 끝"에 어긋난다. 인덱스 품질 문제는 OS 설정으로 푼다(FILE-05가 그 사실을 알린다).

### D-10 랭킹은 frecency다
`base × (1 + log1p(hits) × recency)`. 곱셈이라 매칭 0이면 결과도 0이고, `log1p`라 새 항목이 영영 묻히지 않는다. 최근성은 연속 감쇠 대신 4단계 버킷 — 예측 가능하고 테스트하기 쉽다. **폐기안:** 단순 사용 횟수 정렬 — 한 번 많이 쓴 앱이 영원히 1위에 고정된다.

### D-11 공급원은 비동기로 합류한다
빠른 공급원(앱·계산·스크립트·형제 앱 명령)은 캐시에서 즉시 답하고, 느린 공급원(파일)은 늦게 도착해 `query:more`로 합류한다. 전부 기다렸다 한 번에 그리면 타이핑이 막힌다(SRCH-08). 늦게 온 결과가 이미 고른 항목의 자리를 밀지 않도록, 도착 시점에 선택 중인 항목은 위치를 유지한다.

### D-12 규약은 별도 저장소에 둔다
`when-protocol` — 매니페스트 스키마·예제·각 앱이 붙이는 법. 여섯 앱 어느 쪽에도 두지 않는 이유는, 어느 한 앱에 두면 그 앱이 나머지의 상위가 되기 때문이다. 규약은 코드가 아니라 **구조**라서 "코드를 공유하지 않는다"는 원칙과 충돌하지 않는다.

### D-13 macOS를 1급으로 낸다
지금까지 다섯 앱은 Windows가 주였고 `platform/darwin.mjs`에는 "실기기에서 검증되지 않았다"는 주석이 남아 있다. 이 앱은 macOS에서 개발되므로 양 OS를 동등하게 내고, 미검증 항목 셋을 실측해 형제 앱에 돌려준다(DONE-05).

### D-14 여섯 앱은 코드를 공유하지 않는다 (WHENMUSIC D-17 승계)
2026-09-19에 형제 앱의 중복을 실측해 이 결정을 재확인했다.

| 중복도 | 파일 | 합계 |
|---|---|---|
| 100% 동일 | `settings`(42) `queue`(98) `place`(30) `platform/index`(12) `index`(8) | **190줄** |
| 89~98% | `update`(181) `platform/darwin`(71) `platform/win32`(49) | 301줄 |
| 27~48% | `lifecycle`(574) `store`(683~849) `ipc`(354) | — |

**100% 똑같은 파일은 전부 작고, 큰 파일은 이미 갈라졌다.** `lifecycle.mjs`는 574줄인데 whennote↔whenwork 동일률이 48%, `store.mjs`는 36%다. 공용 패키지로 뽑아도 공통분이 적고, 억지로 합치면 여섯 앱의 서로 다른 요구가 옵션 플래그로 쌓인다. 복제되는 190줄의 복사 비용은 사실상 0이다. **폐기안:** `when-core` 공용 패키지 추출 — 중복이 더 갈라지기 전에 잡자는 안이었으나, 위 분포가 수익이 낮음을 보였고 [D-03](#d-03-형제-앱이-하나도-없어도-온전히-동작한다)의 "따로따로 설치"와도 맞지 않는다(공용 런타임 의존은 앱을 서로 묶는다).

### D-15 결과 종류는 출처 칩으로 드러낸다 (2026-09-19)
`design/mockups/panel-options.html` §1의 다섯 안을 비교해 **㉤ 출처 칩**을 채택했다 — 행 40px · 폭 560px · 최대 8줄 · 하단 바 34px. **(2026-09-21 보충)** 하단 바(로고·`↵ 실행`·`esc 닫기`)는 Windows 실사용 첫날 뺐다 — 키 안내는 두 번 보면 외워지고 그 뒤로는 읽을 것만 늘린다. 입력창 placeholder가 `WHENCOMMAND`로 이름을 대신한다. 출처는 각 줄 오른쪽 끝 알약으로 세우고, 형제 앱만 `--accent` 색점, 스크립트는 `--success`, 앱·파일은 `--text-muted`. **폐기안 ①** ㉣ 종류별 머리글 — 출처가 가장 명확하지만 순위를 종류에 종속시켜 frecency(D-10)를 무력화하고, 느린 공급원이 합류할 때(D-11) 목록이 통째로 재배치된다. **폐기안 ②** ㉠ 두 줄 행 — 부제에 출처가 글자로 섞여 훑을 때 안 보이고 8줄에 406px을 쓴다. **폐기안 ③** ㉡ 입력줄 분리 — `BrowserWindow`가 둘이라 120ms 예산(PANEL-02)에 불리하다.

### D-16 설정은 별도 작은 창이다 (2026-09-19)
입력줄은 순간적이어야 하고(뜨고 → 한 줄 → 사라진다) 설정은 머무는 화면이라 성격이 다르다. 540px 창 하나에 단축키·시작·스크립트·형제 앱·데이터·정보 여섯 섹션. 이 앱의 **유일한 창**이고, 형제 앱 연동 상태(연결됨·설치 안 됨·매니페스트 오류)를 사용자가 볼 수 있는 유일한 자리다. **폐기안** 입력줄 안에서 설정 모드 — 순간적인 창에 머무는 화면을 넣으면 `Esc`·포커스 이탈로 닫히는 규칙(PANEL-05)과 충돌한다. **(2026-09-21 구현 보충)** `main/settings-win.mjs` + `renderer/settings.{html,js}`. 트레이 "설정…"과 입력줄의 내장 명령 `설정`(`sources/builtin.mjs`)으로 뜬다. 높이는 렌더러가 내용에 맞춰 알려 준다(형제 앱 수가 기기마다 다르다). 단축키는 칸을 누르고 조합을 누르는 방식 — 새 조합의 등록을 확인하고 실패하면 이전 조합으로 되돌린 채 이유를 적는다(PLAT-02, whenwork 승계). 자동 실행은 켠 뒤 되읽어 토글을 맞춘다(PLAT-05). 형제 앱 섹션은 연결됨·설치 안 됨·매니페스트 오류 세 상태를 이유와 함께 보이고, 폴더가 없으면 섹션이 사라진다. 설정 내보내기는 `hotkey`·`openAtLogin`·`panel.pos` 셋만(STOR-04) — 랭킹은 담지 않는다. 랭킹 초기화는 버튼을 두 번 눌러 확인한다(대화상자 대신, 3초 안에). 업데이트 확인 줄은 `update.mjs`가 들어오면 붙인다. **(2026-09-21 보충 2)** 형제 앱 줄의 캡션 뒤에 사용법이 접혀 있고(D-25), 창은 작업영역을 넘지 않고 본문이 스크롤된다.

### D-17 스크립트 출력은 길이로 가른다 (2026-09-19)
stdout 3줄 이하 + exit 0이면 **자체 토스트**(우상단 4초, 한 줄이면 자동 복사). 그 밖은 **같은 패널이 아래로 자라** 고정폭 출력을 보인다. 실패(exit ≠ 0)는 stderr 원문과 `경로:줄번호`를 그대로 보이고 조용히 지나가지 않는다(EXT-05). **폐기안** OS 알림 — 권한을 묻고, 알림 센터에 쌓이고, 두 OS 모양이 달라 "같은 앱"(DONE-03)이 깨진다.

### D-18 빈 입력은 입력줄만이다 (2026-09-21)
부르자마자 보이는 것은 입력줄 하나다. 목록도 안내도 미리 채우지 않는다 — 이 앱은 "적으면 된다"이지 "골라라"가 아니고, 부른 사람은 이미 칠 것을 알고 있다. 사용법은 트레이의 첫 실행 알림(PANEL-11)이 맡는다. **폐기안 ①** "자주 쓰는 것 4줄"(SRCH-07 초안, 시안 §1 ①) — 빈 화면을 피하려던 것인데, Windows 실사용 첫날 빼기로 했다. 매번 뜨는 4줄은 읽을 것이 되어 부르는 동작을 무겁게 하고, "적으면 된다"는 이 앱의 성격과도 어긋난다. **폐기안 ②** 첫 실행(3회 미만)에만 사용법 한 줄 — 같은 이유로 바로 뒤따라 뺐다. 입력줄 안에 글이 있으면 그것이 무엇이든 읽게 된다. frecency는 검색 결과의 순서에만 쓴다(D-10). 자주 쓰는 것을 되부르는 길은 `↑`(직전 입력, PANEL-07)로 충분하다.

### D-19 입력줄은 옮길 수 있고 자리를 기억한다 (2026-09-21)
D-08의 위 28% 중앙은 **기본값**이고, 마우스로 끌어 옮기면 그 창 좌표를 `settings.json`의 `panel.pos`에 남겨 다음에도 거기 뜬다. 끌 수 있는 자리는 입력 행과 하단 바(`-webkit-app-region: drag`), 입력창만 뺀다. 저장된 자리가 지금 화면 배치에서 안 보이면 `place.mjs`가 기본 자리로 되돌린다(whenwork와 같은 계산, 같은 테스트). 트레이 메뉴에 "입력줄 위치 되돌리기"를 둔다 — 설정 창(D-16)이 아직 없기도 하고, 되돌리기는 한 번 누르는 일이라 메뉴가 맞다. **폐기안 ①** 고정 위치(D-08 초안) — Windows 실사용 첫날 옮기고 싶어졌다. 어디에 뜰지는 화면 배치와 습관에 달린 것이라 앱이 정할 일이 아니다. **폐기안 ②** 설정 창에서 좌표·비율 입력 — 끌어다 놓는 것보다 나은 점이 없다.

### D-20 스크립트는 상단 주석으로 자기를 소개하고, 실행기는 OS가 고른다 (2026-09-21)
`# name:` · `# description:` · `# icon:`(첫 글자 하나) — 셔뱅 다음 주석 덩어리만 읽고 주석 아닌 첫 줄에서 멈춘다. 키는 한글(`이름`·`설명`·`아이콘`)과 `=`도 받는다. 선언이 없으면 파일명(`-`·`_` → 공백)이 이름이다. 실행기는 `platform.scriptRunner(file)`이 확장자로 정한다 — macOS `.sh/.zsh/.bash`와 확장자 없는 실행 파일, Windows `.ps1`과 `.cmd/.bat`. 모르는 확장자는 목록에 오르지 않는다(README를 두어도 명령이 되지 않는다). 60초를 넘기면 죽이고 실패로 보인다. **Windows 함정 둘:** ① 한국어 콘솔은 cp949라 `-File` 대신 `-Command`로 감싸 `[Console]::OutputEncoding`을 UTF-8로 먼저 세운다(`.cmd`는 `chcp 65001`). ② PowerShell은 파일이 없거나 마지막 명령이 실패해도 `$LASTEXITCODE`가 비어 exit 0으로 끝난다 — `$?`를 함께 봐야 실패가 드러난다(EXT-05). 예제 `.ps1`은 BOM을 붙여 쓴다(5.1이 BOM 없는 UTF-8을 cp949로 읽는다). **폐기안 ①** JSON 매니페스트로 스크립트를 등록 — 파일 하나 더 만드는 순간 "폴더에 넣으면 끝"이 깨진다. **폐기안 ②** 헤더 없이 파일명만 — 설명과 아이콘이 없으면 목록에서 앱과 구분이 안 된다. 토스트는 OS 알림이 아니라 자체 창(D-17)이고, 미리 만들어 두며 `focusable:false` + 클릭 통과로 하던 일을 끊지 않는다.

### D-21 파일은 늦게 합류하고, 같은 이름이면 앱이 앞선다 (2026-09-21)
`sources/files.mjs`는 다른 공급원과 모양이 같지만 `query()`가 빈 배열이고 `late()`가 답한다 — 빠른 공급원의 결과를 먼저 그리고, 파일이 오면 같은 순번일 때만 전체를 다시 순위 매겨 `query:more`로 밀어 넣는다(D-11). 3글자부터(FILE-03), 120ms 디바운스, 1.5s 넘으면 버린다. 합류할 때 **커서까지의 행은 고정하고 그 아래만 점수순으로 섞는다** — 렌더러가 결정한다(메인은 점수만 붙여 보낸다). 첫 안은 전체를 다시 순위 매기고 커서가 항목을 따라가게 했는데, Windows 실사용에서 방향키를 누른 직후 파일이 도착하면 고른 항목이 8줄 밖으로 밀려 커서가 0으로 튀고 목록이 깜빡였다(2026-09-21). 대가: 더 잘 맞는 파일도 커서 아래로만 온다 — 첫 줄이 흔들리지 않는 것이 런처에선 더 중요하다(안 보고 `Enter`). 파일의 매칭 점수에는 **0.85**를 곱한다 — "chrome"은 앱이지 `chrome.txt`가 아니다. 색인이 걸었는데 우리 매칭이 0인 것(현지화 표시 이름 `다운로드`로 걸린 `Downloads` 등)은 바닥 0.15로 그래도 목록에 둔다. Windows는 PowerShell 하나를 띄워 두고 ADODB로 Windows Search를 읽는다(실측 #8) — Everything·자체 색인은 D-09대로 폐기. **폐기안 ①** 파일을 별도 섹션에 아래로 — D-15에서 버린 종류별 머리글과 같은 이유. **폐기안 ②** 파일도 즉시 기다렸다 한 번에 — 타이핑이 막힌다(SRCH-08).

### D-22 명령 제목 뒤에 띄어 쓴 것이 인자다 (2026-09-21)
`메모 검색 회의록` → `whennote://search?q=회의록`. 입력이 명령 제목으로 시작하면(`splitCommand`) 나머지가 **첫 string 인자**이고 점수는 0.95(제목만 정확히 치면 1). 제목으로 시작하지 않으면 제목에 퍼지·초성 매칭, 그리고 앱 이름 매칭×0.7(`whennote`를 치면 그 앱의 명령이 전부 온다). 필수 인자를 안 받았어도 실행은 된다 — 부제가 "뒤에 q를 붙이세요"라고 말하고, 형제 앱이 빈 값을 처리한다(검색창만 여는 식). 인자 없는 명령에 붙은 나머지 글은 버린다. v1은 첫 인자 하나만 — 두 번째 인자부터는 앱이 스스로 묻는다. **폐기안 ①** `명령: 인자`·`명령 > 인자` 같은 구분자 — 배워야 하고, 띄어쓰기보다 나은 점이 없다. **폐기안 ②** 인자를 받는 두 번째 단계(명령을 고르면 입력줄이 인자 모드로) — 한 번 더 `Enter`를 치게 하고, 입력줄이 상태를 갖게 된다. 매니페스트 폴더는 `fs.watch`로 지켜봐 형제 앱이 파일을 떨어뜨리는 순간 목록에 들어온다 — 폴더가 없으면 지켜볼 수 없고, 트레이 "목록 새로고침"이 다시 시도한다. 건너뛴 파일과 이유는 `siblings.skipped()`에 남아 설정 창(D-16)이 보여 준다.

### D-23 아이콘은 보이는 줄만 OS에 묻고 세션 동안 기억한다 (2026-09-21)
`app.getFileIcon(path, { size: 'normal' })`로 OS가 그 파일에 붙인 아이콘을 받아 data URL로 캐시한다(`main/icons.mjs`). 시작할 때 전부 뽑지 않는다 — 렌더러가 **그려진 줄**(최대 8)의 경로만 묻고, 도착하면 그 줄의 상자만 바꾼다(목록을 다시 그리지 않는다). 실측: 8개 콜드 31~152ms·웜 0ms — 단 OS 아이콘 캐시가 비어 있을 때(부팅 직후·처음 보는 exe) 한 번은 **5.6초**까지 걸렸다. 그래서 더더욱 시작 때 뽑지 않고, 목록은 먼저 그리고 아이콘은 도착하는 대로 그 줄만 바꾼다. Windows 시작 메뉴는 `.lnk`라 그대로 물으면 "바로가기" 그림이 온다 → `platform.resolveIconPath`가 `shell.readShortcutLink`로 대상을 풀어 그쪽 아이콘을 받는다. UWP(`shell:AppsFolder`)와 지워진 파일은 null — 첫 글자 상자가 남는다. 파일 결과도 같은 길로 OS 아이콘을 받는다. **폐기안 ①** 시작 시 전부 추출해 디스크 캐시(오픈이슈 #4의 한 안) — 137개면 시작이 0.5초 늘고, 새 앱을 깔면 캐시가 낡는다. 보이는 줄만 묻는 쪽이 비용이 0에 가깝다. **폐기안 ②** UWP 아이콘을 AppX 매니페스트에서 직접 읽기 — 로고 경로·배율 변형이 많아 v1 범위가 아니다.

### D-24 영문 앱에는 한글 별칭이 붙는다 (2026-09-21)
`main/aliases.mjs`의 표(별칭 → 영문 이름 조각) — `크롬: 'Google Chrome'`, `터미널: ['Terminal', 'Windows Terminal', 'iTerm']` 60개 남짓. 앱 목록을 읽을 때 이름에 조각이 들어 있는 별칭을 붙여 두고, 검색은 이름과 별칭 중 최고 점수(별칭은 ×0.95 — 직접 맞은 것을 이기지 못한다). 별칭에도 초성·자판 교정이 그대로 걸리므로 `ㅋㄹ`이 Chrome에 닿는다. 걸린 별칭은 부제로 보인다(제목에는 강조할 글자가 없다). 사용자는 `~/.whencommand/aliases.json`에 `{ "블렌더": "Blender" }`처럼 더한다(같은 별칭이면 사용자 것이 이김, 깨진 파일은 무시). 저장소에는 아무것도 더하지 않는다(D-02). **폐기안 ①** `ko.lproj/InfoPlist.strings`의 현지화 이름 — macOS에만 있고 있는 앱만 해결되며, 앱 하나당 파일을 한 번 더 읽는다. **폐기안 ②** 고른 기록으로 학습(`ㅋㄹ` 쳐서 0개 → 이어 `chrome` 쳐서 골랐으면 연결) — 성격에는 가장 맞지만 첫 번은 못 찾고, 저장소에 쿼리 원문이 들어가 STOR-02("검색어 원문은 남기지 않는다")를 깬다. v2에서 별칭 파일에 **쓰는** 쪽으로 다시 본다.

### D-25 형제 앱 사용법은 설정 창 안에 접혀 있다 (2026-09-21)
형제 앱 다섯이 붙자 "연결됨"은 보이는데 **무엇을 어떻게 치면 되는지**를 알 길이 없었다 — 입력줄은 빈 상태에서 아무것도 미리 채우지 않고(SRCH-07, D-18) 매니페스트는 사용자가 볼 파일이 아니다. 설정 창(D-16)의 형제 앱 줄 오른쪽 "N개 명령"을 **캡션 "사용법 ›"로 만들고**, 누르면 그 줄 아래로 명령별 한 줄이 펼쳐진다 — `메모 검색 ‹q›` · `퀵 메모 [text]` · `메모 창 열기`(`manifest.mjs usageOf`, 필수 인자는 ‹›, 선택은 []). 위에 단축키 라벨과 "제목 뒤에 띄어 쓴 것이 인자다"(D-22) 한 줄, 아래 각 명령의 description과 인자 메모. 인자 이름은 매니페스트의 영문 그대로 — 입력줄 부제("뒤에 q를 붙이세요")와 같은 말이어야 한다. 기본은 **접힘**이고 펼친 앱은 다시 그려도 유지된다(다시 읽기·refresh). 문구는 메인이 만들고 렌더러는 그린다(`settings:get`의 `siblings.apps[].commands[]`). **폐기안 ①** 항상 펼쳐 보임 — 상태표(연결됨·설치 안 됨·매니페스트 오류)가 이 섹션의 본분인데 명령 15줄이 그걸 밀어낸다. **폐기안 ②** 입력줄 빈 상태에 사용법 — D-18과 정면 충돌. **폐기안 ③** 별도 도움말 창 — 창은 하나뿐이다(D-16). **함께 고친 것:** 창 높이 상한 860이 형제 앱 셋만 붙어도 모자라 '정보' 섹션이 잘렸다 → 상한은 `min(860, 작업영역 높이 − 48)`이고 넘치면 **본문만 스크롤**된다(제목줄 고정, `settings.html .body overflow-y`). 렌더러는 `scrollHeight`로 내용 높이를 알려 준다. `SMOKE_SETTINGS=open`이 전부 펼친 채 찍는다.

### D-26 형제 앱 명령에는 그 앱의 실제 아이콘이 붙는다 (2026-09-21)
시안 §3은 형제 앱·내장 명령을 시리즈 색(accent) 글자 상자로 묶었다. 다섯이 다 붙자 WHENMAIL·WHENMUSIC이 둘 다 **M**이라 구분이 안 됐다. 매니페스트 `verify`의 이 OS 경로는 설치 확인(LINK-04)에서 이미 읽는 실행 파일(`.exe`·`.app`)이므로, 그 경로를 항목(`path`)에 실어 보내면 아이콘 캐시(D-23, `icon:get`)가 그대로 OS 아이콘을 준다 — 입력줄(`panel.js iconPath`)과 설정 창(`settings.js fetchSibIcons`) 양쪽. 받기 전과 못 뽑을 때(verify가 없는 매니페스트)는 글자 상자가 그대로 남는다. 내장 명령(`builtin`, `설정`)은 이 앱 자신이라 글자 상자를 유지한다. **폐기안 ①** 글자 상자 유지(시안 §3) — 시리즈 정체성은 출처 칩(`chip.sib`)이 이미 말하고, 아이콘 자리는 구분에 쓰는 편이 낫다. **폐기안 ②** 매니페스트에 `icon` 필드(PNG 경로·data URL) 추가 — 규약이 늘고 앱마다 파일을 하나 더 관리해야 하는데, OS가 이미 exe에서 같은 그림을 준다. **(구현 직후 실측, 2026-09-21)** `app.getFileIcon`이 형제 앱 다섯의 exe 전부에 **기본 실행 파일 아이콘**(없는 exe와 같은 해시)을 줬다 — Chrome·메모장은 진짜가 왔다(`--probe-icons`). 셸 아이콘 캐시에 없는 exe는 셸이 파일을 열어 보지 않고 종류별 기본 그림을 주는 것으로 보인다(탐색기가 한 번도 안 보여 준 `%LOCALAPPDATA%\Programs\…` 설치본). .NET `ExtractAssociatedIcon`은 exe 리소스를 직접 읽어 진짜 32px를 줬다 → `icons.mjs`가 없는 exe로 기본 아이콘을 한 번 구해 두고, 그것과 같은 결과가 온 exe만 `platform.extractIcons`(win32: PowerShell 한 번에 여러 경로, `-EncodedCommand`; darwin: 빈 객체)로 다시 뽑는다. 형제 앱뿐 아니라 앱 목록의 exe에도 같은 폴백이 걸린다. 콜드 폴백은 다섯 개 766ms·재요청 0ms(`--probe-icons`) — 첫 질의에서 글자 상자가 잠깐 보이다 바뀌므로 **형제 앱 아이콘만 시작 1.5초 뒤·매니페스트 변경·목록 새로고침 때 미리 받아 둔다**(`ctx.warmSiblingIcons`). 앱 목록 전체는 여전히 보이는 줄만 묻는다(D-23).
