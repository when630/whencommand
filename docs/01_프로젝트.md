# WHENCOMMAND — 프로젝트 정의

> 형제 앱 [WHENWORK](https://github.com/when630/whenwork)·[WHENNOTE](https://github.com/when630/whennote)·[WHENCALENDAR](https://github.com/when630/whencalendar)·[WHENMUSIC](https://github.com/when630/whenmusic)·[WHENMAIL](https://github.com/when630/whenmail)과 같은 스택·구조·배포 방식을 쓰고, 역할만 나눈다. 요구사항 ID는 [02_요구사항.md](02_요구사항.md), 기술 결정은 [03_기술_스펙.md](03_기술_스펙.md). 2026-09-19 v0.1.

## What This Is

WHENCOMMAND는 **자기 명사를 갖지 않는 앱**이다. 할 일도 메모도 일정도 소리도 만들지 않는다. 단축키 한 번으로 화면 위에 입력줄이 뜨고, 몇 글자를 치면 **앱이 열리거나, 파일이 열리거나, 명령이 실행된다.**

형제 앱이 설치돼 있으면 그 앱들의 명령까지 같은 줄에서 실행된다. 설치돼 있지 않으면 그 항목이 목록에 없을 뿐, 앱은 그대로 동작한다.

창이 상주하지 않는다. 뜨고, 한 줄 치고, 사라진다. 평균 체류 시간이 2초를 넘으면 이 앱은 실패한 것이다.

## Core Value

**하려는 일을 적으면 된다. 그 일이 어느 앱에 있는지 기억하지 않는다.**

기존 도구가 이걸 못 푸는 이유는 세 가지다.

- **Spotlight·시작 메뉴는 앱과 파일까지만 안다.** "어제 적은 그 메모"나 "10초 되감기"는 각 앱 **안에** 갇혀 있어서, 앱을 먼저 찾아 연 다음에야 그 일에 닿는다
- **Raycast·Alfred가 이걸 풀지만 macOS 전용이다.** 두 OS를 오가는 사람에게는 반쪽이고, 확장이 그쪽 생태계에 묶인다
- **형제 앱이 늘수록 외울 단축키가 는다.** 지금 `⌃⌥M`·`⌃⌥N`·`⌃⌥Space`·`⌃⌥C`·`⌃⌥P`·`⌃⌥S`·`⌃⌥←` 일곱 개를 외우고 있고, 여섯 번째 앱이 나오면 여덟 개가 된다. **외우는 비용이 앱 수에 비례해 는다** — 이건 시리즈 자신이 만들어낸 문제다

세 번째가 이 앱을 시리즈 안에서 필연으로 만든다. WHENCOMMAND는 **시리즈의 확장이 만든 문제를 시리즈 안에서 푸는 앱**이다.

## 설계 원칙 — 형제 앱과의 대칭

| | WHENWORK | WHENNOTE | WHENMUSIC | WHENCOMMAND |
|---|---|---|---|---|
| 제1원칙 | 입력 비용 최소화 | 회수 비용 최소화 | 조작 비용 0 | **기억 비용 0** — 어느 앱의 일인지 떠올리지 않는다 |
| 주 UI | 창 | 창 | 우하단 카드 | **화면 위 28% 입력줄** |
| 상주 | 트레이 | 트레이 | 카드 + 트레이 | **트레이만** — 창은 부를 때만 |
| 핵심 명사 | 할 일 | 메모 | 소리 | **없음 — 동사만 있다** |
| 데이터 주인 | 내가 쓴다 | 내가 쓴다 | 남의 앱이 만든다 | **아무것도 갖지 않는다** |

마지막 두 줄이 이 앱의 특수성이다. 형제 앱은 전부 자기 데이터를 갖지만 WHENCOMMAND가 저장하는 것은 **무엇을 얼마나 자주 골랐는지**뿐이다. 그래서 내보낼 데이터도, 잃을 데이터도 거의 없다.

## 페르소나

| | 특성 | 도출되는 요구 |
|---|---|---|
| 주 사용자 | 한국어 사용. **Windows와 macOS를 둘 다 쓴다** (2026-09-19 확인) | 두 OS에서 같은 앱이어야 한다. 한쪽이 부록이 되면 안 된다 |
| 형제 앱 사용 | 다섯 앱을 **전부 쓰지는 않는다.** 필요한 것만 골라 설치한다 (2026-09-19 확인) | 연동은 **있으면 더해지고 없으면 조용한** 구조여야 한다. 형제 앱을 요구하면 안 된다 ([D-03](03_기술_스펙.md#d-03-형제-앱이-하나도-없어도-온전히-동작한다)) |
| 입력 습관 | 한글로 친다. 초성으로 찾는 데 익숙하다 (형제 앱 `search.mjs` 승계) | 초성 검색이 v1 필수. `ㅋㄹ` 로 "크롬"이 나와야 한다 |
| 손 모양 | 형제 앱 단축키를 `Ctrl+Alt+<글자>` 로 통일해 외우고 있다 | **이 앱만 예외로 둔다.** 가장 자주 누르는 키에 두 손가락 조합은 비싸다 ([D-05](03_기술_스펙.md#d-05-단축키만은-os별로-다르게-둔다)) |
| 상황 | 전체화면 IDE에서 작업 중 | 전체화면 위에 떠야 한다. 닫으면 **직전 창으로 포커스가 돌아와야** 한다 |

## 스코프

### 포함 (v1)

**형제 앱 없이도 성립하는 것**이 v1의 뼈대다. 연동은 그 위에 얹는다.

- **입력줄** — 단축키로 뜨고, `Esc`·포커스 이탈로 사라진다. 전체화면 위, 닫으면 직전 창으로 포커스 복귀
- **앱 실행** — 설치된 앱을 초성·퍼지로 찾아 `Enter`로 연다. 두 OS에서 각각 앱 목록을 모은다
- **파일 열기** — OS 인덱스(macOS Spotlight · Windows Search)에 위임해 찾고 연다. 자체 인덱스를 만들지 않는다
- **계산·변환** — 입력줄에 수식을 치면 첫 줄에 답이 뜬다. `Enter`로 복사
- **스크립트 명령** — 지정 폴더의 셸 스크립트가 명령으로 뜬다. 상단 주석으로 이름·설명을 선언한다
- **형제 앱 연동** — 설치된 형제 앱의 명령을 목록에 합친다. 없으면 그 항목이 없을 뿐이다
- **사용 빈도 랭킹** — 자주·최근에 고른 것이 위로 온다. 두 글자로 원하는 게 첫 줄에 오는 것이 목표다
- 두 OS 설치 파일, GitHub Releases 미서명 배포, 자동 업데이트 알림

### 제외

| 기능 | 이유 |
|---|---|
| **자체 파일 인덱스** | macOS Spotlight와 Windows Search가 이미 OS 수준에서 돌고 있다. 같은 일을 다시 하면 배터리와 디스크를 두 번 쓴다. 인덱스 품질 문제는 OS 설정으로 푼다 |
| **JS 확장 런타임** (Raycast식) | 확장 API를 만들면 그 API가 제품이 된다 — 문서·버전·샌드박스·심사가 전부 따라온다. 1인 사용자에게 셸 스크립트가 같은 일을 하고 비용이 0이다 ([D-07](03_기술_스펙.md#d-07-확장은-셸-스크립트다)) |
| **클립보드 히스토리** | 상시 모니터링이 필요해 "부를 때만 뜨는 앱"이라는 성격과 어긋난다. 저장할 것이 없다는 원칙도 깨진다. v2 후보 |
| **창 관리 (타일링·리사이즈)** | macOS는 접근성 권한, Windows는 다른 API로 양쪽을 다 만들어야 하는데 두 OS에 이미 기본 기능이 있다 |
| **형제 앱 데이터 직접 읽기** | 각 앱의 DB를 직접 열면 스키마가 바뀔 때마다 이 앱이 깨진다. 명령 규약으로만 닿는다 ([D-04](03_기술_스펙.md#d-04-연동은-파일-기반-수동적-발견이다)) |
| **웹 검색·AI 답변** | 브라우저와 별도 앱의 일이다. 네트워크를 요구하면 "설치 파일 하나로 끝"이 깨진다 |
| **클라우드 동기화·계정** | 1인 1PC. 랭킹은 기기마다 달라도 되는 데이터다 (형제 앱 동일) |

## 형제 앱과의 경계

| 앱 | 답하는 질문 | 핵심 명사 |
|---|---|---|
| WHENWORK | 뭘 해야 하지 · 뭐가 밀렸지 | 할 일 |
| WHENNOTE | 그때 뭐라고 적었더라 | 메모 |
| WHENCALENDAR | 다음 하나까지 몇 분 남았지 | 시각 |
| WHENMAIL | 이 사람한테 마지막으로 언제 연락했지 | 사람 |
| WHENMUSIC | 지금 뭐가 흐르지 · 방금 그거 좋았는데 | 소리 |
| **WHENCOMMAND** | **이거 어떻게 하더라** | **없음 — 나머지 다섯의 동사에 닿는 길** |

다섯 앱은 전부 **무언가를 보여 주는** 앱이고 WHENCOMMAND만 **아무것도 보여 주지 않는다.** 그래서 기능이 겹칠 위험이 구조적으로 없다 — 이 앱이 하는 일은 형제 앱을 **부르는 것**이지 대신하는 것이 아니다.

접점은 셋이다.

| 지점 | 처리 |
|---|---|
| 전역 단축키 | 형제 앱이 `⌃⌥` 를 쓴다(WHENWORK `Space`, WHENNOTE `M`·`N`, WHENCALENDAR `C`, WHENMUSIC `P`·`S`·`←`). WHENCOMMAND는 **macOS `⌘Space` · Windows `Alt+Space`** 로 그 바깥에 선다 ([D-05](03_기술_스펙.md#d-05-단축키만은-os별로-다르게-둔다)) |
| 화면 자리 | WHENCALENDAR가 상단 중앙, WHENMUSIC이 우하단을 쓴다. WHENCOMMAND는 **화면 위 28% 중앙**이고 순간적으로만 뜬다 ([D-08](03_기술_스펙.md#d-08-입력줄은-화면-위-28-중앙이다)) |
| 명령 연동 | 형제 앱이 매니페스트 파일을 떨어뜨리고 WHENCOMMAND가 읽는다. **양쪽 어느 쪽도 상대를 요구하지 않는다** ([D-04](03_기술_스펙.md#d-04-연동은-파일-기반-수동적-발견이다)) |

여섯 앱은 코드를 공유하지 않는다(모노레포·공용 패키지 없음). 검증된 모듈을 복사해 시작하고 각자 진화한다 — 초성 검색은 `whennote/main/search.mjs`, 창 배치는 `whenwork/main/place.mjs`, 업데이트는 `whenwork/main/update.mjs`, OS 분기는 `whennote/main/platform/`을 가져온다. 공유하는 것은 **스택·모듈 구조·디자인 토큰·빌드/릴리스 파이프라인·테스트 방식**이다 (WHENMUSIC [D-17](https://github.com/when630/whenmusic/blob/main/docs/03_기술_스펙.md) 승계).

## 이 앱이 시리즈에 돌려주는 것

WHENCOMMAND는 **시리즈에서 macOS가 처음으로 검증되는 앱**이다. 형제 앱의 `platform/darwin.mjs`에는 "실기기에서 검증되지 않았다"는 주석이 남아 있다 — 전역 단축키가 조용히 실패하는지, 미서명 앱의 로그인 항목이 실제로 켜지는지, Dock 아이콘이 완전히 빠지는지 셋이다. 이 앱은 macOS에서 개발되므로 그 셋을 실측하고, 결과를 형제 앱에 되돌려 준다 ([03 §실측 로그](03_기술_스펙.md#12-실측-로그)).

## 완료 판정

작성자가 2주 사용한 뒤 **"형제 앱 단축키를 떠올리려다 멈칫한 횟수"가 0에 가깝고, 두 OS 어느 쪽에서도 "이건 이쪽에선 안 되지"라고 생각한 적이 0회**이면 v1 완료.
